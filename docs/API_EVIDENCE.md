# Endstone Music API evidence

Checked 2026-10-13. Repository baseline: TheNINJALLO/endstone-music `841b12e5954f10da444b1d1f21cceb7d5163bc9e`. Endstone source pinned to `v0.11.14` (`03f4189b1535af0870861748fc569f6deac0ad65`). No live server/client was tested.

## Playback implementation

- Exact Python API: `Player.play_sound(location, sound, volume=1.0, pitch=1.0)`, `Player.stop_sound(sound)`, `Player.stop_all_sounds()`. Source: https://github.com/EndstoneMC/endstone/blob/v0.11.14/endstone/__init__.pyi
- Native implementation sends a single PlaySound packet to the chosen player, with fixed position, volume and pitch. There is no seek/offset/follow flag or completion acknowledgement: https://github.com/EndstoneMC/endstone/blob/v0.11.14/src/endstone/core/player.cpp
- Non-spatial playback should use sound objects with `is3D: false`, `stream: true`, and `name: sounds/custom/<file_without_extension>`. Official Mojang schema says is3D controls positional properties and streaming is recommended for long music. Category selects volume grouping. Keeping neutral is compatible with the repository's existing grouping; do not treat category as the no-distance guarantee. https://github.com/Mojang/bedrock-schemas/blob/main/schemas/rp/sounds/index.schema.json (blob SHA `6161e516fd6802995e8b81f96002054b3ba7e494`, checked 2026-10-13)
- Apply schema migration to old generated entries as well as new uploads. Existing plain string entries have no explicit non-spatial setting. If legacy positional trigger behavior must remain, generate a separate non-spatial alias instead of changing shared definitions silently.
- Send one play call per online recipient, at that recipient's location. This also avoids server-side range selectors and command quoting. Restarting every tick/second is not a follow mechanism; it restarts or layers audio. Name targeting and minimumVolume do not establish a persistent moving source.
- Scope stopping to sounds the plugin owns. Never use broad stop-all for ordinary playlist changes. Stop previous track before replay/skip to avoid overlap.
- Late joins cannot seek to current playback position with this API. A deterministic next-track join policy is honest; a from-start policy is not synchronized. Network delay, client loading and server lag mean sample-exact synchronization is not guaranteed.
- `/music` supports play, queue, stop, volume, fade and loop, but the documented syntax has no player selector or seek parameter. Avoid inventing targeted music-command semantics when the direct per-player API is sufficient. Microsoft command docs updated 2026-03-10: https://learn.microsoft.com/en-us/minecraft/creator/reference/content/commandsreference/examples/commands/music?view=minecraft-bedrock-stable and https://learn.microsoft.com/en-us/minecraft/creator/reference/content/commandsreference/examples/commands/playsound?view=minecraft-bedrock-stable
- Non-fading claims apply to controlled generated definitions loaded by the client, not arbitrary vanilla/external sound IDs. Users' volume sliders/muting still apply. Confirm by moving/teleporting far away and changing dimensions in a real client after reconnecting with updated RP.

## Playlists and duration

- `Scheduler.run_task(plugin, callback, delay=0, period=0)` returns Task; `Task.cancel()` exists. Synchronous callbacks can use player APIs. https://github.com/EndstoneMC/endstone/blob/v0.11.14/endstone/scheduler/__init__.pyi
- Use generation/session guards as well as cancellation so stale stop/next-track callbacks cannot affect newer playback.
- Existing repository already depends on pydub/static-ffmpeg. Duration should come from decoded `AudioSegment` or bounded ffprobe on the final emitted OGG, rather than an assumed fixed length. Official ffprobe supports JSON output and selected format entries: https://ffmpeg.org/ffprobe.html . Suggested arguments: `-v error -show_entries format=duration -of json <local_file>`; validate finite positive duration and handle missing tooling/bad audio explicitly.
- Lock playlist pitch to 1 for simple timing, or account for pitch-speed scaling. There is no sound-completion event in the inspected API. Server-tick scheduling can drift relative to client real-time audio when TPS drops; document/test this rather than promise seamless gapless playback.

## Custom items and jukebox

- Normal BP/RP custom definitions are the supported route. Endstone reads the loaded BDS item registry by full ID and builds its block registry from the world's BlockTypeRegistry, so custom namespaced IDs can be resolved without inventing native registration hooks: https://github.com/EndstoneMC/endstone/blob/v0.11.14/src/endstone/core/registry.cpp
- Exact APIs: `ItemStack(type: str, amount=1, data=0)`, `ItemType.get(name)`, `item.type.id`, `BlockType.get(name)`, `block.type` (a string, not BlockType). https://github.com/EndstoneMC/endstone/blob/v0.11.14/endstone/inventory/__init__.pyi and https://github.com/EndstoneMC/endstone/blob/v0.11.14/endstone/block/__init__.pyi
- `PlayerInteractEvent.Action.RIGHT_CLICK_BLOCK` and `.RIGHT_CLICK_AIR` exist. Use `has_item` / `has_block` guards, full identifier matching, and ignore unrelated/left clicks. `event.is_cancelled`, `event.cancel()` and `@event_handler(ignore_cancelled=True)` exist. https://github.com/EndstoneMC/endstone/blob/v0.11.14/endstone/event/__init__.pyi . Actual right-click-air emission for inert custom items/client input modes remains a live-test item; right-clicking a block provides a clear fallback interaction.
- Use a stable real namespaced item ID per playlist; display name/lore alone is not identity. Check operator permission when interacting as well as when giving items or running commands.
- Minimal custom jukebox can be an ordinary data-driven cube, with Endstone storing its playlist binding by dimension and coordinates and handling its clicks. This is not a native vanilla jukebox inventory/record container. Removal, cancelled breaks, explosion/movement and stale coordinate bindings need explicit handling/limits.
- Current official simple-block example uses `format_version: 1.21.80`, `minecraft:geometry: minecraft:geometry.full_block` and `minecraft:material_instances`. Include both geometry and materials. RP terrain atlas entries resolve texture keys; RP blocks.json can supply wood sounds, and texts/en_US.lang supplies name. Source updated 2025-07-31: https://learn.microsoft.com/en-us/minecraft/creator/documents/addcustomdieblock?view=minecraft-bedrock-stable
- Data-driven blocks automatically get a placeable item. A separate `block_placer` replacement item is unnecessary and adds compatibility complexity. Source updated 2024-11-21: https://learn.microsoft.com/en-us/minecraft/creator/reference/content/blockreference/examples/customizingitemforablock?view=minecraft-bedrock-stable
- Modern item icon shape is `minecraft:icon: {textures: {default: <atlas_key>}}`; texture keys come from RP textures/item_texture.json. Singular `texture` is deprecated. Source updated 2026-06-22: https://learn.microsoft.com/en-us/minecraft/creator/reference/content/itemreference/examples/itemcomponents/minecraft_icon?view=minecraft-bedrock-stable
- BP manifest format 2, type data, unique header/module UUIDs, explicit RP dependency matching its UUID/version; RP type resources. Activate both on the intended world while preserving other pack entries. Generation does not register IDs in an already loaded world; restart server/reload world and reconnect clients for content changes. Avoid experimental script custom components for this straightforward Endstone-driven behavior.
- Content format 1.21.80 is below advertised 1.26.52.3 target and uses stable components; it is a schema choice, not proof of live compatibility. Current geometry docs note changed bottom-face orientation at format 1.26.0 and require geometry+materials from 1.21.80: https://learn.microsoft.com/en-us/minecraft/creator/reference/content/blockreference/examples/blockcomponents/minecraftblock_geometry?view=minecraft-bedrock-stable (2026-06-22).

## Follow-up API checks

- `server.level.get_dimension(name)`, `dimension.loaded_chunks` (Chunk.x,z), `dimension.get_block_at(x,y,z)` are exact v0.11.14 APIs. Check chunk coordinates using floor division before reading; no Python is_chunk_loaded API was found. Native loaded_chunks enumerates existing loaded chunk storage, without loading more. https://github.com/EndstoneMC/endstone/blob/v0.11.14/endstone/level/__init__.pyi and https://github.com/EndstoneMC/endstone/blob/v0.11.14/src/endstone/core/level/dimension.cpp
- `player.inventory.add_item(ItemStack(id, 1))` returns a dict of leftovers. Empty means all added; handle a full inventory. Player.is_sneaking is a bool property.
- Air interaction is driven by BDS ItemUseEvent, so do not promise arbitrary inert item air clicks: https://github.com/EndstoneMC/endstone/blob/v0.11.14/src/endstone/runtime/bedrock_hooks/script_item_gameplay_handler.cpp . Right-block is driven by PlayerInteractWithBlockBeforeEvent: https://github.com/EndstoneMC/endstone/blob/v0.11.14/src/endstone/runtime/bedrock_hooks/script_player_gameplay_handler.cpp .
- BlockBreakEvent is pre-destroy; cancellation prevents the action. MONITOR plus ignore_cancelled observes final ordinary plugin intent, and deferred verification can confirm actual removal. MONITOR must not modify the event. Source: https://github.com/EndstoneMC/endstone/blob/v0.11.14/src/endstone/runtime/bedrock_hooks/script_block_gameplay_handler.cpp .

## Command registration

Endstone v0.11.14 uses typed overloads such as `<id: str>`, `<track: int>` and `[seconds: float]`. Untyped `[args...]` is not a variadic argument. A message-type trailing argument would be delivered as a single string, so this implementation registers explicit overloads for each playlist command. Sources: https://github.com/EndstoneMC/endstone/blob/v0.11.14/src/endstone/core/command/command_usage_parser.cpp and https://github.com/EndstoneMC/endstone/blob/v0.11.14/docs/tutorials/register-commands.md .

The exact command type map accepts both `str` and `string` for single-word identifiers, `int` for integer parameters and `float` for numeric parameters. Singleton enums (`<playlist>`, `<add>`) are valid. This build uses `str` consistently in both plugin class and pyproject command metadata. Source: https://github.com/EndstoneMC/endstone/blob/v0.11.14/src/endstone/core/command/command_map.cpp#L431-L448 .
